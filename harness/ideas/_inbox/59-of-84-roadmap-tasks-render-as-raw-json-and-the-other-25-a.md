# 59 of 84 roadmap tasks render as raw JSON and the other 25 as blank flashcards or option-less questions, so a learner cannot do a single task

## Why
First real learner (owner, 2026-09-25, live roadmap generated by `nvidia/nemotron-3-super-120b-a12b:free` via OpenRouter): "I can't learn with the current UI… I can't focus at least 30 minutes." The root is not taste, it is a contract gap between what the roadmap model returns in each task's `content` and what `frontend/utils/content.ts` / `components/learn/ContentViewer.vue` can render:

| what the model produced (84 tasks) | what the viewer does |
|---|---|
| 22 vocabulary tasks: `content.words[]` with keys `english`/`definition` (109 words, **0** with `term`) | flashcard shows an **empty** front (`word.term`), only the definition |
| 28 reading tasks: `content: {passage}`; 28 practice tasks: `content: {instruction}` — 59 total with neither `words` nor `questions` | `kind: 'raw'` → the JSON is dumped in a `<pre>` block |
| 3 tasks with `content.questions[]` (6 questions): **0** have `options`, **0** have an answer key | question text with no choices; nothing to submit, nothing graded |

On top of that the learning room (`pages/learn/[id].vue`) disables "Hoàn thành" until the 10-minute countdown reaches 0 regardless of content, so the learner stares at a `<pre>` block for ten minutes per task. Spec §7.3 promises "Câu 2 / 10 … (A)(B)(C) … Gửi đáp án"; §6.1 promises "gamified, micro-animated". Neither exists today. This is the happy path for every learner, so it outranks everything else in the queue.

The approved medium plan `2026-09-24-typed-task-content-with-answer-keys-so-every-quest-renders-a` (backend half: per-type `content` schema with answer keys asked for in the prompt and enforced by `ParseRoadmap`) is the right first move and should be **re-prioritised high and executed first**; this bug adds the frontend half and the model-output evidence it lacked.

## Expected output
- Backend (the existing plan, raised to high): the roadmap prompt demands and `ParseRoadmap` enforces per-type shapes — vocabulary `{words:[{term, definition, example}], questions:[…]}`, reading `{passage, questions:[…]}`, practice `{questions:[…]}`, every question `{id, prompt, options:{A,B,C,D}, answer, explanation}`; a roadmap that fails validation is rejected and regenerated once, never stored. Key names match the frontend types exactly (`term`, not `english`).
- Frontend half (new): `ContentViewer` renders each type — flashcard with term/definition/example and a "got it / again" flip, passage then questions, practice questions — with **instant feedback** (correct/incorrect + explanation) from the answer key, and never a raw `<pre>`; a task whose content still fails classification shows a friendly "this task is being regenerated" state and a retry, not JSON.
- The learning room completes **by doing**: "Hoàn thành" enables when the last item is answered; the timer keeps counting real time for `daily_progress.minutes_spent` (the approved plan `2026-09-25-task-timer-keeps-counting-through-reloads…` covers persistence) but no longer gates completion.
- A migration/one-off that regenerates (or marks for regeneration) roadmaps stored before the contract, so the owner's current roadmap is replaced rather than left broken.
- Vitest: one test per content type + raw fallback; Go: `ParseRoadmap` rejects each malformed shape above (fixtures taken from this live output).
