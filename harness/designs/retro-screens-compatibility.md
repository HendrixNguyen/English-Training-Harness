# Binding compatibility addendum: complete the remaining retro screens

Designer audit against origin/main 61c30ef8e326e276d4d09513bc929093311e367d, 2026-10-13. Reuse `harness/UI-KIT.md` v2 and the six existing `retro-*` designs; this addendum supersedes their obsolete API and learning-flow assumptions. Kit v2 supersedes frontend spec §6 colors/type; spec §7 route intent survives. No new visual language or sound/theme/inventory system.

## Learner jobs and return value
Hub: see real progress and enter the next task in one tap; companion growth makes effort visible. Room: learn from each answer and retain results; feedback is the reason to continue. Onboarding: trust the level and begin real tasks; hatch/real day-one titles reward placement. Roadmap: understand actual completed and missed days; the current region shows the next destination. Revive: see study since the challenge started and restore the companion. Settings: know what reminder/integration actually works, then leave quickly. Avoid fake rewards, decorative progress that substitutes for data, and hidden/doubled primary actions.

## Required deviations from the old designs
- **Room lifecycle is released behavior, not a rewrite.** Preserve ContentViewer/session helpers, lazy hydration/repair, glossary focus/look-back, owner/task/revision draft scope, sessionEpoch guards, authoritative reconciliation and accepted completed-result cache. Selection → submit → feedback → Continue; last Continue → explicitly unsaved summary → explicit save → authoritative saved result. Never POST automatically on last Continue. No offline save queue exists: keep draft and disabled save with an honest reconnect instruction, not “tớ sẽ ghi lại khi có mạng”. No timer expiry or Next can bypass required questions. Existing countdown presentation may be restyled without changing elapsed-time semantics; timer never gates completion.
- Vocabulary words/examples remain study material followed by the required vocabulary quiz. Old self-rating deck must not replace that quiz or cause a task to finish without answers. Do not create duplicate ItemQuestion/ItemFlashcard engines where existing ContentViewer supports the lifecycle. Completed tasks show saved score/time/answers read-only and never re-save. Historical null score/time remain unknown; keyless results remain ungraded.
- Chest is presentation of known result only. Actual duration comes from server quiz_result.duration_seconds; do not hard-code +10 minutes or +20 HP. Optional pet_health/streak_count omission means unknown, not zero or guessed reward. XP may be omitted; if implemented, label session-only and never persist or claim server reward.
- **Hub shields unavailable:** current PetStatus has plant_name, health_points, stage, current_streak, last_practiced_at; no shields field. Omit shield rack rather than invent earned shields. First-day/healthy/wilted copy uses actual plant_name. Retain released row-state/navigation behavior; no new task unlocking rule.
- **Onboarding regeneration now exists:** POST /api/v1/roadmaps/regenerate with JSON `{cefr_level}` (not `?level=`). Returns status, assessed_level, roadmap_id. Assessment remains synchronous; no 202 background-poll generation API exists. Waiting is visible during real request, preserves answers on failure, and does not promise an exact one-minute completion. Calibration can ship against this endpoint, clamps CEFR A1–C2, displays disabled boundary controls, has an explicit “Vừa sức” keep action, and refreshes real daily tasks after successful replacement. Do not navigate away before ready data resolves. Placement has no answer keys or correctness feedback.
- **Roadmap backend missing:** origin/main mounts no GET /api/v1/roadmap; old page manufactures past-day completion from day_number. Full four-region design therefore requires the existing roadmap-tree contract to be implemented as a backend prerequisite within the approved plan. Do not fabricate modules/titles/completion from daily data. Required owned DTO: roadmap title/cefr_level/current day and modules[{week,title,focus,days[{day_number,date,title,tasks,minutes_spent,is_target_met}]}]. Register/document/test actual route before wiring page. Stars derive solely from is_target_met, partial from recorded minutes, missed from past local date, locked from future date. After the final calendar day, no perpetual “today” on day28. Missing per-task completion is unknown, not “Đã xong”. No past-day catch-up endpoint in scope.
- **Settings endpoints exist, readback absent:** POST settings/notifications and integrations/google/sync are mounted. No GET settings or auth user notification_time exists today. Owner scope now requires a narrow GET /api/v1/settings/notifications prerequisite; render persisted server values, loading/retry until available, never local-only settings truth. Time wire HH:MM:SS plus IANA timezone; push_subscription flattens endpoint,p256dh,auth. Use response notification_time,next_reminder_at for success. Saving time alone does not prove push enabled or Google reminder active. Do not claim Google fallback unless sync was confirmed. Preserve unsupported/no-key/denied states after time saves. No push-removal endpoint: browser unsubscribe is allowed as the existing settings design specifies; state/copy must distinguish this-device unsubscribe from deleting all server subscriptions. Permission only from explicit tap; key comes from public config, never hard-coded. Sync errors/permission refusal are recoverable; no fake success or count.
- Sign-out calls central auth.signOut so previous-owner drafts/cache are cleaned before identity drops. Confirm dialog must be accessible, have plain “Đăng xuất” meaning, trap focus, restore focus on cancel, Escape cancel, and disable duplicate confirmation.

4. **Roadmap:** owned real modules/focus/titles, four regions and 28 days; five honest states with text/glyph; current-region sprite and navigation to hub; cleared/partial/missed expand real task titles and minutes one at a time; locked inert. ## Scope and tradeoffs
Reuse established designs rather than produce new mock architecture. Truthful roadmap and persisted settings GET endpoints are required narrow backend prerequisites; reuse existing repositories and document additive DTOs. Omit unavailable shields and optional XP rather than expand backend gamification. No staged generation, writing grading, spaced review, catch-up, sound, inventory, push unsubscribe, or persistent XP are silently included. This keeps the restyle complete while protecting the learning feature just released.

## Task 1 additive GET contracts (required before screen wiring)
- **GET /api/v1/roadmap**, bearer-authenticated and scoped to authenticated user only. Reuse roadmap-tree design ownership, current roadmap selection and local-calendar rules. Body `{roadmap_id,title,cefr_level,today,day_number,modules:[{week,title,focus,days:[{day_number,date,title,minutes_spent,is_target_met,tasks:[{id,task_type,title,duration_minutes,is_completed}]}]}]}`. `today` is learner-IANA-timezone YYYY-MM-DD; current day can exceed28 (no clamp for today UI). Derived SQL daily-progress flags are authoritative; absent completed day records are zero/false, never “past therefore cleared”. Existing progress stores completion IDs? If historical per-task completion cannot be reconstructed reliably, `is_completed` must be nullable and render unknown instead of fabricating false/true. No answer keys/content payload needed. `404 no_active_roadmap`; unauthorized401; transient errors5xx. Read must not generate AI or change roadmap/task IDs.
- **GET /api/v1/settings**, bearer-authenticated/owned, server read only. Minimum body `{notification_time,timezone,next_reminder_at,push_configured}`. Time is persisted HH:MM:SS with the existing preferences fallback semantics; timezone IANA, next_reminder_at is server-computed RFC3339 prospective next time for that preference (not proof queued/sent). `push_configured` means server VAPID public/private present, not this device permission; never expose subscription endpoint/key material. UI determines this-device capability/permission/actual SW subscription separately. If Google persisted sync state is added, body `google_sync:{status, tasks_created_count}` must report complete synchronization for current roadmap only, otherwise `status:"not_synced"`, count0; never require this optional addition or manufacture timestamp. Do not infer linked Google from public profile. Settings reload must recover actual saved notification_time/timezone from GET. No secrets in response. Missing user404 user_not_found,401 unauthorized, read failure5xx.
- Existing **POST /settings/notifications** preserves `{status:"updated",notification_time,next_reminder_at}` and permission-independent time saving; flat optional push_subscription. Existing **POST /integrations/google/sync** preserves `{status:"synced",calendar_event_id,tasks_created_count}` and idempotent behavior; new UI must use actual error codes from handler (reauth_required/Google errors), not assume a design-only google_not_linked code. Existing **POST /roadmaps/regenerate** remains JSON `{cefr_level?}` and `{status,assessed_level,roadmap_id}`. Add DTO/spec/CODEMAP documentation and owned/read-only/error/local-date tests. Avoid private GET worker caching unless owner-scoped provenance and fresh bypass exist; normal network read with explicit memory cache is sufficient.

## Final screen acceptance evidence (2026-10-13)

Task 7 checked the six screen designs above against the production Nuxt bundle at 375×812, 1280×900, and 200% CSS layout zoom at 375px with DPR 1. The reproducible runner is `frontend/tests/e2e/retro-visual.mjs` after `npm run build`; it writes 25 labelled screenshots and `visual-manifest.json` under `LEARNING_PROOF_LOGS` (default `/workspace/cloud-setup/retro-screens/task7`). Its route fixtures are used only for edge and visual states: login, onboarding, hub, roadmap, revive, settings, placement turn, sign-out dialog, keyboard focus, loading, error, and offline. It asserts each route's expected heading/state before capture, checks both document/body width and control bounds, scrolls the hub to ensure its last task clears the sticky action, and exercises dialog focus wrap, Escape, and opener restoration. Zoom screenshots include all six primary routes and the sign-out dialog; the actual-service reading suite also captures the learning room at 375px and zoom.

The released learning path was exercised separately through the real Go API, disposable PostgreSQL and Redis, signed fixture sessions, and a deterministic OpenAI-compatible provider. `LEARNING_COMPOSE_PROJECT=retro-screens LEARNING_PROOF_LOGS=/workspace/cloud-setup/retro-screens/task7 PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npx playwright test --config playwright.reading.config.ts` passed all 19 cases: reading, vocabulary, practice, measured save/grade, draft resume, offline and lost-response reconciliation, owner/cache isolation, and central sign-out through `/settings`. The provider fixture proves transport, persistence, and UI lifecycle; it does not establish generated content quality.
