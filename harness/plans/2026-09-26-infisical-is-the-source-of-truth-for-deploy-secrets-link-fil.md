# Infisical is the source of truth for deploy secrets: `.infisical.json` in the repo, an "Env source of truth" runbook section, Railway sync by Infisical — Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Team:** Feature team — ticket **F4** of 2026-09-26. **Estimate:** 1.5 h. **Branch:** `harness/2026-09-26-medium-infisical-is-the-source-of-truth-for-deploy-secrets-link-fil`.

**Idea:** `harness/ideas/2026-09-25-run-01/infisical-is-the-source-of-truth-for-deploy-secrets-link-fil.md`. Documentation and one JSON link file; no code, no design doc.

**Goal:** From any checkout, `infisical login && infisical export --env prod --format dotenv > deploy/.env` rebuilds the production env; the runbook says so first, says how to push changes back (`infisical secrets set`, blank values filtered), and states that Railway variables come from Infisical's Railway secret sync, not from hand edits.

**Rules:** agents never see or write secret values; `.infisical.json` holds only `workspaceId` and `defaultEnvironment`. Never commit `deploy/.env` (already gitignored by `.env*`; verify with `git check-ignore deploy/.env`).

**⚠ Same-day note:** bug plans B4/B5 edit other sections of `deploy/README.md` (Target A Pages paragraph, *Environment* table, *Smoke check*). This plan adds a **new** section "Env source of truth" between *Environment* and *Target A* and edits only the *Owner checklist* — no overlap; merge `origin/main` first if they are already there.
